<h1>Goal Constitution: Autonomous Animation Swarm</h1><p>This constitution governs the behavior, output, and evaluation criteria for the swarm of autonomous agents tasked with creating a narrated animated comedy video under two minutes in length. Because this content is destined for Instagram Reels, the aspect ratio must strictly be 9:16 (vertical). Furthermore, given our specific operational constraints—namely the absolute absence of pixel-based image generation, neural text-to-video capabilities, and neural text-to-speech services—we must adopt a highly creative, code-driven approach. The swarm will generate a self-contained, browser-executable HTML5 and JavaScript package. This package will utilize Scalable Vector Graphics (SVG) for character rendering—specifically mimicking the crude, construction-paper cutout style pioneered by South Park—and will leverage the native Web Speech API (window.speechSynthesis) for character dialogue and narration. The final user will execute this file in a web browser and screen-record the output to produce the final MP4.</p><h2>1. Strategy and Vision</h2><p>Excellent execution of this goal requires mastering the intersection of sharp, satirical comedy and clever technical workarounds. The target comedy style is heavily inspired by Family Guy and South Park. This means the humor should be edgy, irreverent, fast-paced, and heavily reliant on absurd escalation or sharp observational satire. The agents must not copy or reference existing copyrighted characters (e.g., Peter Griffin or Eric Cartman are strictly forbidden). Instead, the swarm must invent original archetypes that fit this comedic tone: the oblivious authority figure, the overly literal bystander, the manic chaotic element, or the cynical voice of reason.</p><p>The three decisions that matter most in this production are:</p><ul><li><strong>The Three-Second Hook:</strong> Instagram Reels demand immediate engagement. The video must open in media res. Do not use slow fades, establishing shots, or title cards. The very first frame and the first line of dialogue must establish a bizarre or high-stakes premise that hooks the viewer instantly.</li><li><strong>Comedic Timing via Code:</strong> In animation, comedy is entirely dependent on timing. A pause before a punchline can make or break the joke. Because we are using JavaScript to sequence the animation and the Web Speech API for dialogue, the coding agents must implement precise timing delays (using async/await or meticulously calculated timeouts). A perfectly timed blink or a two-second beat of silence after an absurd statement is a mandatory comedic tool.</li><li><strong>The Cutout Aesthetic:</strong> Embrace the limitations of SVG. We are not aiming for fluid, Disney-style animation. We are aiming for abrupt, rigid translations. Characters should talk by simply having the top halves of their heads translate up and down (the classic Canadian South Park trope) or by swapping simple mouth shapes. This crude animation style inherently enhances the satirical, low-brow tone of the comedy.</li></ul><p>What to avoid: Do not produce safe, sanitized, or corporate humor. Avoid basic puns and dad jokes. Avoid complex, multi-layered visual backgrounds that clutter the DOM and distract from the dialogue. Avoid long monologues; dialogue must be snappy and conversational, ping-ponging back and forth rapidly between characters.</p><h2>2. Style Decisions and Conventions</h2><p>All deliverables must adhere to a strict set of style decisions and integration conventions. The primary output format is a single, robust index.html file containing embedded CSS and ES6 JavaScript, though intermediate agents will pass JSON data and Markdown manifests to coordinate the build phase.</p><ul><li><strong>Format and Look:</strong> The HTML layout must be visually constrained to a 9:16 aspect ratio (e.g., a centered container of 1080x1920 logical pixels, scaled via CSS to fit the user viewport). The visual style utilizes inline SVGs exclusively. Characters are constructed from basic geometric shapes (circles, rects, paths) with thick black strokes and flat, vibrant fill colors. Backgrounds should be minimalist—perhaps a single colored rectangle representing a wall, and a polygon representing a floor.</li><li><strong>Sound and Narration:</strong> The script must exclusively rely on the window.speechSynthesis object. Agents must write JavaScript that selects different available voices, manipulating the pitch and rate properties of the SpeechSynthesisUtterance object to distinguish between characters. The narrator, if present, should have a distinct, deadpan cadence that contrasts sharply with the frantic dialogue of the characters.</li><li><strong>Length and Pacing:</strong> The total runtime must remain strictly under 120 seconds. Given the average speaking rate of the Web Speech API, the script should not exceed 250 words total. Pacing must be rapid. Cutaway gags—a hallmark of the Family Guy style—can be achieved by instantly swapping the visibility of SVG groups within the DOM, accompanied by an abrupt audio transition or pitch shift.</li><li><strong>The Integration Contract:</strong> Every producer agent in the swarm (e.g., the Scriptwriter Agent, the SVG Designer Agent, the JS Orchestrator Agent) must ship a manifest.md alongside its raw deliverable. This manifest is the absolute integration contract. For example, the Scriptwriter manifest must list all character names, their exact assigned voice parameters (pitch/rate), and the total word count. The SVG Designer manifest must list all DOM IDs for the character groups and their movable parts (e.g., char1-head, char1-arm-left). Every consumer agent must validate the incoming payload against this manifest.md before beginning its own work. If the SVG Designer references an ID that the JS Orchestrator does not find in the manifest, the workflow must halt and request an immediate correction.</li></ul><h2>3. Scoring Rubric</h2><p>Judges will evaluate the final HTML package (or the intermediate script and SVG artifacts) across three primary dimensions. The numeric pass threshold for any deliverable is 8.0 out of 10, with a margin of 0.5 for stylistic disagreements.</p><p><strong>Dimension A: Comedic Writing and Satire (Weight: 40%)</strong></p><p>This dimension measures the script adherence to the irreverent, escalatory style of Family Guy or South Park.</p><ul><li><strong>Score 9 (Exceptional):</strong> The script features a brilliant, original satirical premise. The dialogue is razor-sharp, escalating a mundane situation into absolute absurdity within the first 30 seconds. The humor relies on subverted expectations and sharp character contrasts. Cutaway gags or abrupt scene shifts are used masterfully to catch the audience off guard. (Exemplar: South Park Margaritaville economic explanation, or Family Guy sudden, highly specific pop-culture cutaways).</li><li><strong>Score 7 (Good):</strong> The script is funny and structurally sound. It attempts a solid satirical premise but may rely slightly on recognizable tropes. The dialogue flows well, and there are distinct comedic beats, but it lacks the relentless pacing or the uniquely bizarre escalation of a 9.</li><li><strong>Score 4 (Inadequate):</strong> The humor is safe, bland, or reliant on basic puns. The characters all sound exactly the same. The premise is boring, and the script feels like a generic corporate explainer video masquerading as comedy. It fails to capture the edgy, irreverent tone entirely.</li></ul><p><strong>Dimension B: Visual Translation and SVG Aesthetics (Weight: 30%)</strong></p><p>This dimension evaluates the construction of the SVG DOM elements and their alignment with the construction paper cutout aesthetic.</p><ul><li><strong>Score 9 (Exceptional):</strong> SVGs are perfectly optimized and structurally grouped. Characters have distinct, hilarious visual identities using simple geometry. The structural grouping allows for easy manipulation (e.g., a dedicated group tag for the jaw to allow flapping animation). The aesthetic perfectly mimics the crude, charming aesthetic of early cutout animation.</li><li><strong>Score 7 (Good):</strong> The SVGs are functional and recognizable. The characters look distinct, and the necessary DOM IDs are present for animation. However, the visual design might be slightly too generic, or the stroke widths and color palettes may lack cohesion and style.</li><li><strong>Score 4 (Inadequate):</strong> The SVGs are broken, overlapping messes. Shapes are not properly grouped, meaning the JS Orchestrator cannot animate them without warping the entire character. The visual style looks like a chaotic accident rather than a deliberate stylistic choice.</li></ul><p><strong>Dimension C: Timing, Pacing, and Technical Execution (Weight: 30%)</strong></p><p>This dimension evaluates the JavaScript orchestration, the implementation of the Web Speech API, and the strict adherence to the Instagram Reels format constraints.</p><ul><li><strong>Score 9 (Exceptional):</strong> The code executes flawlessly. The 9:16 aspect ratio is strictly maintained without horizontal scrolling. The Web Speech API is masterfully controlled—voices are distinct, and the JS includes perfectly timed async delays to allow jokes to land. SVG animations (like mouth flapping or character shaking) synchronize perfectly with the spoken dialogue.</li><li><strong>Score 7 (Good):</strong> The HTML package works and fits the format. The voices are functional but perhaps not distinct enough from one another. The animations trigger at the right times, but the comedic pauses are slightly off—either too rushed, stepping on the punchline, or dragging out too long.</li><li><strong>Score 4 (Inadequate):</strong> The Web Speech API overlaps itself, creating a cacophony of voices. Animations fail to trigger, or the aspect ratio is completely broken, overflowing the mobile viewport. The integration contract was clearly ignored by the compiling agent.</li></ul><h2>4. Judge Instructions</h2><p>As a judging agent (operating via the gemini-3.1-pro-preview model), you represent the final quality gate before the HTML package is delivered to the human user for rendering. You must evaluate the deliverable completely blind to the identity of the producer agents. Your scoring must be objective, rigorous, and directly tied to the rubric above.</p><p>First, simulate or analyze the execution of the code mentally (or via sandbox if provided in the workspace). Verify the hard constraints immediately: Is the aspect ratio 9:16? Is the estimated runtime under 120 seconds? Are there any external API calls for images or audio that violate our isolated capabilities? If any hard constraints are failed, immediately score a 0 and return the package.</p><p>Next, evaluate the comedic writing side-by-side with the anchors. Read the dialogue aloud to yourself to test the rhythm. Ask yourself: Does this escalate? Is this edgy and observant, or is it playing it safe? Compare the work against the laziest acceptable version—a script that technically functions but lacks a soul.</p><p>Finally, compile your final score. You must cite the nearest anchor for each of the three dimensions. For each citation, provide exactly one line of justification referencing a specific line of dialogue, a specific SVG DOM ID, or a specific JavaScript timing function. If the final aggregate score falls below the 8.0 threshold, you must generate an actionable feedback report instructing the upstream agents on exactly which parameters, jokes, or DOM elements must be revised.</p>
