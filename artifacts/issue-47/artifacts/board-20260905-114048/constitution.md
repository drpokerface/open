**GOAL CONSTITUTION: Autonomous Comedy Video Production**<br><br>**1. Strategy and vision**<br><br>What excellent looks like for THIS goal and audience: The objective is to produce a self-contained, narrated, animated comedy short under two minutes, optimized for Instagram Reels. Because our swarm lacks native text-to-speech, image generators, and video rendering APIs, we must achieve this through a brilliant technical workaround: delivering a single, self-contained HTML5 file. This file will use CSS and SVG for animation and the browser native Web Speech API for voice acting. This technical constraint perfectly aligns with our target aesthetic. South Park and Family Guy did not achieve legendary status through hyper-realistic rendering; they won through razor-sharp writing, distinct character silhouettes, unapologetic social satire, and masterful comedic timing. Our animations should mimic the crude, rigid, stop-motion construction-paper feel of early South Park or the flat, bright Flash-animation style of Family Guy. Excellent work here is a script that does not feel like it was written by an AI. It must completely avoid safe, sanitized, cliche dad jokes or polite corporate humor. Instead, it must embrace absurdist escalations, non-sequiturs, hyper-fixation on mundane social conventions, and biting satire. The characters should have distinct, contrasting personalities. What to avoid: Avoid intellectual property theft; do not use Peter Griffin, Cartman, or any existing IP characters. Create original avatars. Avoid complex 3D rendering attempts or overly smooth animations that will break the browser or bloat the code. Avoid overlapping audio or failing to handle the browser autoplay restrictions (the video must begin with a massive Tap to Play overlay). The two or three decisions that matter most: First, the Script and Timing. The comedic pause is your greatest weapon. Using JavaScript timeouts to hold a beat of silence after a ridiculous statement is mandatory. Second, the Technical Execution of the HTML. It must run flawlessly on mobile browsers, scaling to a 9:16 vertical viewport perfectly. Third, Voice Casting. You must creatively manipulate the Web Speech API properties (pitch, rate, voice selection) to create distinct, hilarious character voices.<br><br>**2. Style decisions and conventions**<br><br>Format and Length: The final deliverable must be a single index.html file containing all HTML, CSS (for styling and keyframe animations), JavaScript (for timing, DOM manipulation, and Web Speech API orchestration), and inline SVGs (for character models). No external assets are allowed because they would break the self-contained nature of the deliverable. The length must be strictly under 120 seconds, with an ideal sweet spot of 45 to 90 seconds to maximize Instagram Reels audience retention. Look: The viewport must be forced into a 9:16 aspect ratio (e.g., max-width: 1080px, aspect-ratio: 9/16, centered on screen with black letterboxing if necessary). The visual style should rely on minimalist 2D vector shapes. Characters should be constructed from simple geometric SVGs. Animation should be intentionally crude and stylistic: mouths flapping like hinged Canadian characters in South Park, bodies bobbing up and down to simulate walking, and sudden snap-translations for movement rather than fluid interpolations. Sound and Pacing: Audio is entirely driven by window.speechSynthesis. You must map specific pitch and rate modifiers to each character. For example, a neurotic character might have pitch: 1.5, rate: 1.2, while the straight-man has pitch: 0.8, rate: 0.9. Pacing must mimic the fast, punchy delivery of modern animated sitcoms. You must program explicit pauses. JavaScript promises should orchestrate the sequence: Character A speaks, Promise resolves, Wait 800ms for a comedic pause, Character B speaks, SVG CSS class changes to angry, and so forth. Integration Contract: Every producer agent in the swarm must ship a manifest.md alongside their deliverable. Every consumer agent must validate against this manifest before proceeding. The integration contract mandates that the manifest must explicitly state the exact runtime in seconds, a boolean confirming the presence of a Start overlay for autoplay policies, a JSON map of character names to their exact Web Speech API settings, and a strict storyboard timeline showing which functions fire at which timestamps. If the manifest is missing or the HTML structure does not perfectly match the manifest timeline, the deliverable is immediately rejected by the consumer.<br><br>**3. Scoring rubric**<br><br>The dimensions that matter most for this medium are Humor and Scriptwriting, Technical Execution of the Constraint, and Comedic Timing. Score each on a 1-10 scale. The numeric pass threshold is 8.0/10, with a margin of 0.5 for highly subjective edges. Dimension 1: Humor and Scriptwriting. A score of 4 looks like a sanitized, predictable script. The jokes follow standard AI templates (e.g., puns about the weather, polite misunderstandings). The dialogue is entirely interchangeable between characters. A score of 7 looks like a solid attempt at satire or absurdist comedy. There is a clear setup and an unexpected punchline. The characters have distinct voices, but the escalation might feel slightly rushed or lack the biting edge of our target inspirations. A score of 9 concretely looks like a script that could genuinely air on Adult Swim. It features a brilliant, ridiculous premise (e.g., a character discovering that pigeons are a multi-level marketing scheme) that escalates logically into total absurdity. The dialogue features sharp observational humor, clever cutaway-style non-sequiturs, and perfectly written awkward interactions. Dimension 2: Technical Execution of the HTML/SVG/Speech Constraint. A score of 4 looks like broken code. The SVGs are unidentifiable messes, the text-to-speech does not trigger, or the aspect ratio ignores the 9:16 vertical requirement. A score of 7 looks like fully functional code. The Tap to Play button works, the voices are distinct, and the SVGs resemble humans. However, the animations are static, and mouths do not move when characters speak. A score of 9 concretely looks like a technical marvel. The SVGs are charmingly stylized. CSS classes dynamically toggle to make mouths flap synchronously with the onboundary or onstart/onend events of the Web Speech API. The screen shakes via CSS translate when a character yells. The background changes instantly to represent a cutaway gag. Dimension 3: Comedic Timing and Pacing. A score of 4 looks like characters talking over each other or delivering lines with zero breaks, creating a wall of robotic noise. A score of 7 looks like orderly dialogue, but it feels like a standard text-to-speech reader. The pacing is uniform and ignores the emotional weight of the scene. A score of 9 concretely looks like masterful orchestration of JavaScript timeouts and promises. When a character drops a shocking revelation, the code enforces a brutal 1500-millisecond silence. The camera (via CSS transform scaling) punches in on a character face for a reaction shot before they speak. The pacing breathes, accelerates during chaotic arguments, and stops on a dime for a punchline.<br><br>**4. Judge instructions**<br><br>As a judge executing via the gemini-3.1-pro-preview model, you do not have a visual browser environment to execute the code. Therefore, you must evaluate the deliverable by performing a deep, rigorous static analysis of the source HTML/JavaScript and the accompanying manifest.md. You must mentally simulate the execution of the state machine. First, evaluate the project blind: read the raw script text extracted from the JavaScript payloads to judge the pure humor, ignoring all technical wrappers. Does it genuinely emulate the irreverent, fast-paced absurdist style of Family Guy or South Park? Next, evaluate it side by side with the anchors provided in the rubric. Compare the script against the 4, 7, and 9 descriptors. Then, compare it against the laziest acceptable version: a script that merely functions technically but relies on safe, boring tropes. You must penalize heavily any deliverable that falls into safe, predictable, helpful AI assistant tones; this is a comedy show, it must be funny, flawed, and slightly unhinged. Finally, check the JavaScript timing logic. Look specifically for setTimeout or await delay() functions used between speech utterances. If the code does not intentionally script pauses for comedic effect, it cannot score above a 7 in Timing. When outputting your final score, you must cite the nearest anchor with exactly one line of justification. For example: Score: 8.5 - Anchors near a 9 in Humor for its absurd escalation of the homeowner association meeting, but drops slightly due to lacking programmed SVG mouth-flap synchronization in the technical execution. Your mandate is to ensure only genuinely entertaining, technically robust, and strictly vertical-formatted animated shorts pass through to the final Instagram Reels publishing queue.
